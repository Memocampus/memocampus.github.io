1. Scope and Operator

This Privacy Policy ("Policy") explains how Memocampus (GitHub Organization: https://github.com/Memocampus) handles user data in the Memocampus software.

This Policy applies to the following components:

  • The Memocampus Google Chrome extension (Extension ID: cdklofjfcjagkaclekmicliailmlnfla)
  • The local Windows companion components (Native Messaging Host, tray supervisor, and read-only MCP server memocampus-mcp)
  • This official website (https://memocampus.github.io/)

Memocampus v0.8.0 is currently being prepared for Chrome Web Store review. The last updated date is shown at the top of this page.

2. Data Handled

All data handled by Memocampus is stored locally on your own device (in your local Vault and local configuration directory). Automatically recorded data and data saved or entered through explicit user actions are distinguished as follows:

Category Data Items Trigger and Notes
Automatic Recording (Visits) Visited URL, page title, visit timestamp (UTC), and navigation transition metadata (transition type, redirect/new-tab/forward-back flags, and reference to source visit) Recorded when a main-frame http:// or https:// page finishes loading in a standard window after you explicitly start recording.
Automatic Recording (Page Metadata) document.title, meta[name="description"], Open Graph attributes (og:title, og:description, og:site_name, og:image URL), favicon URL, and capture timestamp Read only after Privacy Gate allows the URL, inspecting HTML metadata attributes only. Automatic recording does not collect page body text.
User-Initiated Save (Tab Snapshots) URL, title, window ID, tab index, pinned state, and timestamp of open non-incognito tabs Recorded when you click the "Record all tabs" action in the side panel (subject to Privacy Gate).
User-Initiated Save (Images) Original image bytes (PNG, JPEG, GIF, WebP, AVIF, BMP; up to 32 MiB; deduplicated by SHA-256), generated thumbnail (WebP/JPEG), image URL (for data: URLs, only the subtype prefix is stored), page URL, frame URL, saved timestamp, and incognito flag Recorded when you explicitly save an image via the context menu. SVG images are not supported.
User-Initiated Save (MHTML Pages) MHTML snapshot bytes (multipart/related; up to 128 MiB; deduplicated by SHA-256), page URL, page title, and capture/save timestamps Recorded via chrome.pageCapture.saveAsMHTML when you explicitly save a page via the context menu. Refused in incognito tabs.
User Input & Configuration Image tags (local-only), search queries and date filters, Privacy Gate rules and imported CSV rules, custom Vault paths, Recovery Spell, and backup passwords (never stored) Data entered or configured by you in the UI. Backup passwords are used only during encryption/decryption and are never saved.

3. Recording Start and Scope

  • Explicit First-Time Start: Automatic recording does not start upon installation. You must create or select a Vault and explicitly start recording during onboarding. Navigations started before the recording start timestamp are not backfilled.
  • Excluded from Automatic Recording: Non-http:///https:// schemes (such as chrome://, about:, file://, and chrome-extension://), incognito windows, subframes (iframes), prerendered pages, and SPA pushState/replaceState transitions are excluded from automatic visit recording.
  • Privacy Gate Enforcement: Automatic visits and tab snapshots are checked by Privacy Gate before queueing, before flushing, and in the Native Host before storage. If the policy is uninitialized, corrupted, or unreadable, Privacy Gate fails closed—halting new automatic recording and displaying a warning badge on the extension icon.
  • When Saving May Fail: Recording or saving can fail if the Native Messaging Host is unreachable, the URL or format is unsupported, size limits are exceeded, incognito restrictions apply, disk/permission errors occur, or the policy cannot be read.

4. Storage Location and Encryption

  • Local Vault: Data is stored in a single SQLite file (local Vault) on your PC. %LOCALAPPDATA%\Memocampus\memocampus.sqlite3 is only a suggested default path during setup and is never created automatically upon installation or startup without your action. A Vault becomes active only when you explicitly create one or select an existing file, and if a configured Vault file goes missing, Memocampus will not recreate it automatically.
  • User-Selected Locations & Restrictions: You may select a custom local folder. Network paths (UNC), network drives, optical drives, RAM disks, and the application executable directory are rejected. Cloud-synced folders (such as OneDrive, Dropbox, or Google Drive), removable drives, and non-NTFS/ReFS filesystems require a warning and explicit user approval.
  • SQLCipher 4 Encryption: Newly created encrypted Vaults (the default) encrypt the entire database (visits, metadata, images, thumbnails, tags, and MHTML pages) using SQLCipher 4, with temporary database operations kept in memory (PRAGMA temp_store = MEMORY).
  • Windows DPAPI and Recovery Spell: The Vault encryption key is derived via HKDF-SHA256 from a vault-specific salt and a 43-character Recovery Spell generated from OS cryptographic randomness. The Recovery Spell is shown once at creation and must be confirmed before committing. For daily use, a Windows user-scoped DPAPI-protected key cache (under %LOCALAPPDATA%\Memocampus\keys\) allows opening the Vault without re-entering the Recovery Spell each time.
  • Unencrypted Items & Security Limits: Plain-mode Vaults (if selected), configuration and policy files (config.json, policy.json, domain-approvals.json), startup logs (which do not include URLs or titles), and transient queued events in chrome.storage.local awaiting host delivery are not encrypted by SQLCipher. Encryption reduces the risk of unauthorized reading of the Vault file at rest, but it does not protect against all threats—such as malware running under the same Windows user account, direct access to an unlocked device, or a leaked Recovery Spell.
  • Backup and Restore: Memocampus supports standard backups (for encrypted Vaults, .mcbackup requiring Recovery Spell verification) and password-protected backups (Argon2id + XChaCha20-Poly1305). Restoring always creates a new Vault file without overwriting existing ones, and MCP publication starts as pending (closed).

5. Privacy Gate (NeverSave and SaveButNoMcp)

Memocampus provides two distinct URL rule zones to control local recording and MCP visibility separately:

NeverSave (Blind Zone)

  • Includes built-in rules for authentication pages, URLs containing credential parameters (such as tokens or passwords), Japanese government portals (*.myna.go.jp, *.nta.go.jp), webmail, and major AI chat services, plus your custom rules.
  • Suppresses automatic visit recording and tab snapshots for matching URLs, and purges matching unsent events from the pending queue.
  • MCP queries also re-evaluate existing records against the current policy, so matching records are hidden from MCP.
  • Important Notice: Adding or changing a NeverSave rule does not automatically delete records already stored in the Vault, and does not block explicit manual image saving or manual MHTML page saving triggered by you from the context menu.

SaveButNoMcp (Private Zone)

  • Matching URLs are recorded locally in your Vault as usual.
  • However, they are completely excluded when the MCP server (VisibleStore) answers queries—omitted from visit search, daily listings, domain statistics, and image lookups.

6. MCP and External AI Services

Storing data locally in your Vault is fundamentally separate from sharing data with external AI services through MCP (Model Context Protocol).

  • Vault-Level MCP Publication Opt-In: MCP publication approval is tracked only for the single active Vault file identity and is separate from MCP client connection settings. Creating a new Vault, opening an unapproved Vault, switching to another Vault (including switching back to a previously approved Vault), restoring from a backup, converting Vault format (plain/encrypted conversion or Recovery Spell reissue), or opening a copied or replaced file always sets publication to pending (closed); the MCP server refuses access until you explicitly approve publication via the Native Host. Approval is preserved only when re-opening the exact same currently active approved Vault file. You can revoke approval at any time, which immediately closes MCP access and remains closed upon re-opening.
  • Strictly Read-Only Capabilities: memocampus-mcp is strictly read-only and cannot modify your Vault or configuration. It exposes only 5 tools: searching public visits, listing public visits by day, retrieving public domain statistics, searching metadata of explicitly MCP-public images, and retrieving thumbnails (up to 256 KiB) of those public images.
  • Protection of Private Data: Records matching NeverSave or SaveButNoMcp, images not individually marked MCP-public, images saved from incognito windows (which cannot be published to MCP), original image bytes, image tags, tab snapshots, navigation transition events, and saved MHTML pages are never exposed to MCP.
  • Possible Transfer to External AI Providers: Once you approve MCP publication and connect an MCP client (such as a desktop AI application), data returned by MCP tools (such as visited URLs, titles, page metadata, or image thumbnails) is handed to that MCP client and may be transmitted to and processed by external AI model providers or cloud services.
  • Scope of Memocampus's Control: Memocampus can only control what data its local MCP server returns. Once data is passed to an MCP client, Memocampus cannot control how that client or any external AI provider transmits, stores, retains, or uses that data; those practices are governed by the respective client's and AI provider's terms and privacy policies.

7. Developer Data Handling and Network Activity

Based on the current implementation of the product components (extension, Native Messaging Host, VisibleStore, MCP server, tray supervisor, and installer) and this website:

  • No Transmission to Developer Servers: Memocampus does not implement any feature that sends your browsing history, images, MHTML pages, or Vault files to developer-operated servers.
  • No Analytics, Telemetry, Ads, or Sale of Data: We do not collect analytics or telemetry, run behavioral tracking, use tracking cookies, serve advertisements, or sell user data to third parties. This website also uses no external CDNs, external fonts, or analytics scripts.
  • Observed Network Interactions & External Boundaries:
    • When you explicitly save an image via the context menu, the extension may issue a fetch request to the target image URL to retrieve the image bytes for local storage.
    • When you explicitly enable the optional Streamable HTTP transport on memocampus-mcp, it listens strictly on local loopback (127.0.0.1 or [::1]) with mandatory Bearer token authentication, no CORS headers, and rejection of requests carrying an Origin header.
    • When you connect an external MCP client, that client may communicate with external AI services.
    • Other browser or OS-level network activity (such as normal web browsing in Chrome, Chrome Web Store extension updates, or cloud syncing if you approve a cloud-synced folder for your Vault) occurs outside Memocampus's control.

8. Data Management, Deletion, and Backups

  • User Management and Deletion: From the extension UI, you can preview and delete individual visits, filtered visits, all records for a specific URL, saved images (individually, by tag, or all), and saved MHTML pages. Deletions are executed immediately without a recycle bin (SQLite VACUUM is not run automatically).
  • Residual Data After Deletion: Deleting data in the application is not the same as permanently erasing it from your storage medium (such as an SSD or HDD). Memocampus performs standard SQLite DELETE operations (using the default DELETE rollback journal mode) and does not automatically run VACUUM or secure_delete. As a result, deleted data may remain in unallocated space (freelist pages) within the Vault file until overwritten by future writes, or briefly in a transient rollback journal during active transactions. Protection of residual data differs by Vault mode: in an encrypted Vault (SQLCipher 4), database pages—including freelist and journal pages—remain encrypted (though recovery may remain possible for someone holding the Vault key), whereas in a plain Vault, unallocated space remains unencrypted. Normal deletion in Memocampus does not guarantee secure physical erasure on storage media.
  • Retention in Backups: Deleting items from your active Vault does not alter or remove data inside previously created backup files (.sqlite3 or .mcbackup). Delete old backup files manually if you wish to remove them.
  • Uninstallation and Your Vault: Uninstalling Memocampus via the Windows installer removes the application executables, tray autostart entry, and Native Messaging registration, but does not delete your Vault files or the %LOCALAPPDATA%\Memocampus data folder in order to protect your local data. To remove Vault files permanently, delete them manually from your filesystem.

9. Chrome Web Store User Data Policy (Limited Use)

The Memocampus Chrome extension uses data accessed through Chrome extension APIs (visited URLs, tab information, page metadata, and user-initiated image/MHTML captures) solely to provide and maintain its prominently disclosed user-facing features: local Vault recording, search, organization, archival, and user-approved local read-only MCP integration.

  • We do not use user data for advertising, personalized targeting, creditworthiness determinations, data brokering, or any purpose unrelated to Memocampus's core user-facing functionality.
  • We do not sell or transfer user data to third parties. If you explicitly approve MCP publication and connect an external MCP client, queried data is passed to that client as described in Section 6.
  • User data stays on your local device; no human on the developer side accesses or reads your Vault data.

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements.
