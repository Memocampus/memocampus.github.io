Keep your web memory on your own device.

Memocampus is personal software that stores your web browsing records and manually saved images and pages in a local Vault on your own PC so you can search and rediscover them later. Rather than handing your history to a cloud service, it is designed to keep your data under your local control.

Read Privacy Policy GitHub Organization

What is Memocampus?

Memocampus is not a simple bookmark manager. It records the flow of what you visited and when, along with page titles, page metadata, and images or MHTML page snapshots you choose to preserve, storing everything in a local database (Vault) so you can revisit your web memory later.

It works as a combination of a Google Chrome extension and local Windows components (Native Messaging Host, tray supervisor, and a read-only MCP server). Automatic recording never starts silently upon installation; you explicitly start recording only after creating or selecting a Vault.

Key Features

Browsing Records, Search & Calendar View

Records standard-window http:// and https:// visits (URL, title, timestamp, page metadata, and navigation transitions). Rediscover past visits via keyword search or calendar filtering in the side panel and full history view.

Manual Saving (Images, MHTML & Tab Snapshots)

Save images (with original bytes, thumbnails, and local tags) or full MHTML page snapshots via the context menu. You can also capture a manual snapshot of all open non-incognito tabs from the side panel.

Data Management, Export & Deletion

Review and delete individual visits, filtered visits, URLs, saved images, or MHTML pages. Export saved images and MHTML files, and create or restore Vault backups into new files without overwriting existing ones.

Local Vault and Encryption

Recorded data is stored not on a developer-operated server, but in a single local SQLite file (local Vault) on your PC. %LOCALAPPDATA%\Memocampus\memocampus.sqlite3 is only a suggested default path during setup and is never created silently upon installation or startup. You explicitly create a Vault or select an existing file, and Memocampus will not automatically recreate a configured Vault if it goes missing (you may also choose a custom local folder; network drives are blocked and cloud-synced folders require explicit approval).

  • SQLCipher 4 Encryption: Newly created encrypted Vaults encrypt the entire SQLite database using SQLCipher 4.
  • Windows DPAPI & Recovery Spell: For daily convenience, the Vault key is cached using user-scoped Windows DPAPI. Recovering or opening the Vault on another environment uses a 43-character Recovery Spell shown once at creation.
  • Backup & Restore: Supports standard and password-protected backups (Argon2id + XChaCha20-Poly1305). Restoring always creates a new Vault file rather than overwriting an existing one.

Security Notice: Encryption strengthens protection of the Vault file at rest, but it does not defend against every threat—such as malware running under the same Windows user account, unauthorized access to an unlocked device, or a leaked Recovery Spell. See the Privacy Policy (Storage Location and Encryption) for details.

Privacy Gate

Memocampus includes a Privacy Gate (policy engine) to separate areas you never want recorded automatically from areas you want kept local and hidden from AI tools. It is designed to fail closed: if the policy is uninitialized or unreadable, automatic recording stops.

NeverSave (Blind Zone)

Prevents automatic recording for URLs matching built-in rules (such as authentication pages, credential parameters, government portals, webmail, and major AI chats) or your custom rules. Note that NeverSave does not automatically delete existing Vault records, nor does it block explicit manual image or MHTML page saves.

SaveButNoMcp (Private Zone)

Saves visits locally in your Vault as usual, while completely excluding them from MCP search, statistics, and retrieval.

MCP Integration (Read-Only, Explicit Opt-In)

Memocampus includes a local, strictly read-only MCP server (memocampus-mcp) that lets compatible AI clients query only the Vault data you have explicitly approved for MCP exposure.

  • Closed by Default & Explicit Opt-In: Newly created, switched (including returning to a previously approved Vault), restored, or converted Vaults start as MCP-closed (pending) until you explicitly approve publication (approval is preserved only when re-opening the exact same currently active approved Vault file). You can revoke approval at any time. See the Privacy Policy (MCP and External AI Services) for details.
  • Per-Image Opt-In: Saved images default to private. Only non-incognito images you individually mark as MCP-public can be queried, and only their metadata and thumbnails are returned (original image bytes, tags, and saved MHTML pages are not exposed to MCP).
  • Boundary with External AI Services: While Memocampus itself operates locally (over stdio or opt-in loopback-only HTTP), any data returned to an MCP client may be sent by that client to external AI providers according to their own policies.
